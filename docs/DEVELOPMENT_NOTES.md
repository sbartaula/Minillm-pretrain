# Tenslam MiniLM

A from-scratch, decoder-only Transformer language model (~30M parameters: 8 layers,
d_model 512, 8 heads, 512-token context, 8,192-token byte-level BPE vocabulary),
pretrained from random weights on TinyStories. Educational, portfolio-quality project.

**Status: Session 3 complete (data and training pipeline, CPU-verified).** Full pretraining has
not started. No pretrained weights are downloaded or used anywhere; the tokenizer is trained
only on our own training sample.

## Dataset

- **Source:** [`roneneldan/TinyStories`](https://huggingface.co/datasets/roneneldan/TinyStories)
  (Eldan & Li, 2023, *"TinyStories: How Small Can Language Models Be and Still Speak
  Coherent English?"*), short synthetic stories generated by GPT-3.5/GPT-4.
- **Licence:** CDLA-Sharing-1.0 (per the dataset card). Derived datasets/models should
  respect its sharing terms; re-check the card before publishing anything.
- **Revision pinned** in [configs/data.toml](configs/data.toml) so data cannot drift.
- **Streaming only:** `load_dataset(..., streaming=True)` + a seeded buffered shuffle;
  only the first 10,000 train and 1,000 validation rows are ever read.
- **Splits:** the tokenizer is trained on the train sample only. The validation sample
  comes from the official `validation` split (independent seed) and is also checked for
  exact-duplicate leakage against train.

## Layout

```
configs/data.toml        all parameters (seed, revision, sample sizes, vocab, paths)
src/tenslam/data.py      streaming sampler, JSONL + hashing helpers
src/tenslam/preprocess.py  deterministic cleaning, validation, exact de-duplication
src/tenslam/tokenizer.py byte-level BPE training / encode / decode
src/tenslam/stats.py     corpus statistics
src/tenslam/cli.py       `tenslam` command
tests/                   offline unit tests
data/processed/*manifest.json   dataset manifests (revision, seed, hashes, versions)
artifacts/tokenizer/     tokenizer.json + tokenizer_meta.json
reports/data_report.json statistics and rejection counts
```

`tenslam all` runs the four pipeline steps in order.

> If your shell sources ROS (`PYTHONPATH=/opt/ros/...`), ROS pytest plugins leak into the

## Design decisions

- **Mojibake repair.** ~6.5% of stories contain UTF-8 curly quotes decoded as cp1252
  (`â€™`, `â€œ`...). They are repaired, then typographic punctuation is folded to ASCII.
  This is lossy by design: it keeps the corpus almost pure ASCII so BPE merges are not
  wasted on corrupted byte sequences. The closing quote lost its last byte upstream, so
  the bare `â€` -> `"` repair is a best guess.
- **Whitespace.** Trailing spaces before newlines are stripped, runs of 2+ spaces/tabs
  collapse, paragraph breaks (`\n\n`) are preserved.
- **Document boundaries.** Documents are never merged or split. Each is encoded
  separately and terminated with `<|endoftext|>`, which is how Session 2 will pack
  sequences without losing story boundaries.
- **Special tokens:** `<|pad|>`=0, `<|bos|>`=1, `<|endoftext|>`=2.
- **Byte-level BPE** (GPT-2 style regex pre-tokenizer): no `<unk>`; every string is
  encodable and decodes losslessly.

## Reproducibility

Seed, dataset revision, library versions, and SHA-256 hashes of raw/clean files and the
tokenizer are stored in the manifests and `tokenizer_meta.json`. Re-running `collect`
reproduces the raw files bit-for-bit; re-training the tokenizer gives an identical
`tokenizer.json`.

## Model (Session 2)

[src/tenslam/model.py](src/tenslam/model.py), configured by [configs/model.toml](configs/model.toml):
pre-norm decoder-only Transformer, 8 layers, d_model 512, 8 heads (head_dim 64), RMSNorm,
rotary position embeddings, causal attention via `F.scaled_dot_product_attention`, SwiGLU MLP
(d_ff 1408), no biases, tied input/output embeddings, GPT-2 style 1/sqrt(2L) residual init.
**29,893,120 parameters** (4,194,304 embedding + 25,698,816 non-embedding). Random init only.

`tenslam check-model` runs the three pre-GPU checks on 512 real tokens:
1. **Forward:** logits shape (B, T, 8192), finite, initial loss ~ ln(8192) = 9.01.
2. **Backward:** every parameter receives a non-zero gradient and changes after one AdamW step.
3. **Overfit:** the loss on one fixed batch falls below 10% of its start (observed 9.00 -> 0.0001).

## Session 3: pretraining pipeline and GPU readiness

Nothing here has been run on a GPU. **GPU throughput and cost are unknown** until the benchmark is run on CUDA with an explicit price.

### Data preparation
`tenslam prepare` streams (or reuses `data/raw/*.jsonl`), cleans, drops exact duplicates and docs containing special-token text, removes validation docs overlapping train (exact hash and case/whitespace-insensitive), then writes `uint16` token files (`doc EOS doc EOS ...`) plus `data/tokens/prepare_manifest.json` (counts, sha256, tokenizer hash, config, dataset revision).
Local subset: 49,952 train docs / 10,984,035 tokens; 1,000 validation docs / 203,799 tokens.

### Packing semantics
Training samples random 513-token windows from the flat token stream; `x = w[:-1]`, `y = w[1:]`. Windows are **not** aligned to document starts, **loss does cross documents** and attention is **not** masked at EOS. EOS is an ordinary target, so the model learns to end stories. This is the standard GPT-style choice; a window may begin mid-story. Sampling is stateless, `rng(seed, step, micro)`, so resume is exact. Validation uses fixed non-overlapping windows.

### Kaggle alternative (not the active deployment target)
Kaggle notebook GPU access is generally quota-limited rather than charged by the hour. Check
the current accelerator quota shown in your Kaggle account before enabling a GPU; availability
and quotas can change. For an estimate of **direct money charged**, use `--price 0` only if
Kaggle confirms the selected accelerator is free for your account. This does not mean GPU quota
or time is unlimited. Omit `--price` if you want the estimator to keep monetary cost marked
unknown.

1. On Kaggle, choose **Create > Dataset**, upload `tenslam-minilm-kaggle.zip`, and create the
   dataset. Then choose **Create > Notebook**, set Internet on, and add that dataset as an input.
2. In a notebook cell, unzip the archive from `/kaggle/input/<your-dataset-slug>/` into
   `/kaggle/working/tenslam-minilm/`. Use Kaggle's **Add Input** panel to find the mounted path.
3. Keep the accelerator set to **None** while installing and preparing the corpus. In notebook
   cells, run `pip install -r requirements-kaggle.txt` and then
   `pip install -e . --no-build-isolation` (keep Kaggle's CUDA torch).
4. Run `tenslam prepare --config configs/data_kaggle.toml` for about 600k stories (~125M tokens).
   Save the resulting `data/tokens_kaggle/` folder as a Kaggle output/dataset so the GPU notebook
   does not need to stream and tokenize the corpus again.
5. In a GPU notebook, add both the source and prepared-data datasets, copy their files into
   `/kaggle/working/tenslam-minilm/`, then benchmark with
   `tenslam benchmark --config configs/train_kaggle.toml --sweep 16,32,64 --price 0`
   (omit `--price 0` if you prefer a cost marked unknown).
6. Review benchmark throughput, VRAM, time, and quota implications before training. Only after
   that review (Session 4), run
   `tenslam train --config configs/train_kaggle.toml --resume auto`. A stop (SIGINT/SIGTERM or
   `max_hours`) saves `last.pt`; rerun the same command to continue.

### RunPod (active target; prepare locally, rent only for the benchmark)
RunPod prices depend on GPU, cloud type, location, storage and availability. Check the exact
hourly price and any volume or data-transfer charges in the RunPod UI before creating a Pod.
Convert the listed rate to EUR/hour and pass it to `--price`; the estimate only includes GPU
hours. Keep the total estimate and other charges within the project's €8 ceiling.

Prepare the larger corpus on the laptop first, so GPU rental time is not spent streaming and
tokenizing. This is a CPU data-preparation step:

```bash
cd /path/to/tenslam-minilm
source .venv/bin/activate
unset PYTHONPATH
tenslam prepare --config configs/data_runpod.toml
zip -qr ../tenslam-runpod-data.zip data/tokens_runpod
```

This samples 600,000 training stories and 5,000 official validation stories and writes token
files plus a manifest. The generated data archive is separate from the small source bundle.

1. Upload `tenslam-minilm-runpod.zip` and `tenslam-runpod-data.zip` to a private RunPod Network
   Volume or using the Pod file interface. Persistent storage may have a separate charge.
2. Choose a PyTorch/CUDA template with a compatible NVIDIA GPU. Check the complete price shown
   before deploying. Do not create a Pod until its price and storage charges fit the budget.
3. Open the Pod's web Terminal/Jupyter interface. Extract the source and data archives into the
   project directory, then run
   `pip install -r requirements-runpod.txt && pip install -e . --no-build-isolation`.
   Keep the template's CUDA-enabled PyTorch; do not install the laptop CPU lockfile.
4. Verify CUDA with `nvidia-smi` and
   `python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"`.
   If CUDA is false, stop and do not run the benchmark.
5. Run the short benchmark only:
   `tenslam benchmark --config configs/train_runpod.toml --sweep 16,32,64`.
   This leaves money cost marked unknown. To calculate it, append `--price` and the actual
   dashboard rate converted to EUR/hour (for example, `--price 0.50` only if that is the real
   rate). Review throughput, VRAM and estimated cost before considering training. Storage
   charges are additional.
6. Full pretraining is a separate, later decision. After the benchmark and budget are reviewed,
   adjust `micro_batch_size` and `max_hours` in `configs/train_runpod.toml`, then run
   `tenslam train --config configs/train_runpod.toml --resume auto`. When finished, stop or
   terminate the Pod in the RunPod UI and check whether attached storage continues billing.
